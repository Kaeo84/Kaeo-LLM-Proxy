Architecture Overview

Dual-Protocol Proxy

The proxy translates between Ollama API (client-facing) and OpenAI-compatible API (upstream). Model listing endpoints are answered locally from proxy configuration.

Tool Call ID Correlation (MapMessagesWithToolCorrelation)

Purpose: OpenAI-compatible upstreams reject tool replies whose tool_call_id does not match a preceding assistant tool_call. Ollama clients may send tool replies without IDs. The proxy correlates them by order or function name.

The algorithm: 1) Each assistant message with tool_calls enqueues (id, function.name) pairs. 2) Each subsequent role:"tool" message without a tool_call_id dequeues the next pending pair and assigns its ID.

XML Tool Call Extraction

When enabled: Models that emit tool calls as inline XML (<tool_call><function=name>...</function></tool_call>) are parsed and converted to structured tool_calls. This works in both streaming and non-streaming modes. The XML content is stripped from the visible content field and finish_reason is forced to "tool_calls".

Thinking Compatibility

Trailing assistant prefill removal: When ShouldApplyThinkingCompatibility() returns true for a model, a trailing assistant message (without tool_calls or tool_call_id) is removed before sending upstream. This prevents issues with thinking models that interpret trailing assistant messages as response prefill.
Consecutive system messages: Multiple leading system messages are merged into a single system message, as some upstream providers reject consecutive system messages.

Capability Token Mapping

BuildOllamaCapabilities (for /api/tags, /api/show, /api/ps)

Maps operator-configured capability tokens to Ollama-native tokens. Returns null (field omitted from JSON) when no capabilities are configured.

Proxy Token (ModelCapabilities)Ollama TokenNotes
textcompletion
chatcompletionMerges with text/code
codecompletionMerges with text/chat
function_callingtools
visionvisionSame name
embeddingsembeddingSingular in Ollama
reasoningthinking
image_generationimage
audioaudioSame name

Output is ordered to match Ollama's Go source canonical order: completion, tools, insert, vision, embedding, thinking, image, audio

BuildCapabilities (for /v1/models)

Returns the raw proxy tokens (not Ollama-mapped) in canonical order. Used for OpenAI-style model listing where clients expect OpenAI-style token names.

Critical Behavior

Null vs Empty Array: When no capabilities are configured, both functions return null, which causes System.Text.Json with WhenWritingNull to omit the field entirely from JSON. This is critical: an empty array "capabilities": [] would tell clients (like Visual Studio) that the model has zero capabilities, making it appear unavailable for chat. Omitting the field tells clients to assume default capabilities.

Header Filtering (ShouldSkipRequestHeader)

These headers are not forwarded to upstream:

  • Host, Content-Length, Transfer-Encoding
  • Connection, Upgrade, Keep-Alive
  • Proxy-* headers
  • X-Forwarded-* headers
