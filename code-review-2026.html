3Path map & Mermaid diagram

Every request enters at one listener and leaves through one of four dispositions.

3.1 Ingress and gating

  • ProxyServer (ProxyServer.cs:41) binds an HttpListener prefix http://{host}:{port}/. 0.0.0.0 is rewritten to +; a bind failure with Win32 error 5 is translated into the exact netsh http add urlacl command to run.
  • A single accept loop awaits GetContextAsync() and funnels every context through a SemaphoreSlim sized from MaxConcurrentRequests. No slot within 5 s means a recorded 503 shed, not an unbounded queue.
  • Each accepted request is dispatched fire-and-forget onto the thread pool; the slot is released in a finally that tolerates the gate having been disposed during shutdown.

3.4 Log classification boundary

ClassifyNonProxied (OllamaProxyHandler.cs:1298) decides which of the two request stores a completed request lands in. The rule is deliberately method-and-path only, never status: health probes, version, explorer, local stubs, and GET /v1/models* file under Non-proxied; anything addressed to a model (including a malformed body on /api/chat) stays in the Proxy log; everything else is Rejected. The inline remark at lines 1284–1296 explains why status cannot be used, and that reasoning is sound.

Small drift found here. The routing table answers /api/ps only for GET and /api/show only for POST, but the classifier at line 1318 matches path is "/api/ps" or "/api/show" regardless of verb. A POST /api/ps or DELETE /api/show therefore falls through to the routing table's 404 branch yet is filed as LocalStubs — a rejected request hidden in the stub category. See finding 5.5.

4What is genuinely good

This is not a codebase that needs rescuing. Several areas are better than typical production code.

Comment quality is exceptional and explains why, not whatstrength

Remarks capture the failure mode that motivated the code and the consequence of getting it wrong. The classification boundary (OllamaProxyHandler.cs:1284–1296) explains that UpstreamPath is assigned optimistically before the body is parsed, so routing alone must decide the log category — and states the accepted consequence. The HEAD-probe guard at 1390–1394 names the exact exception (ProtocolViolationException) it prevents. The deadlock-free client-disposal comment at line 101 explains why a fixed delay is unsafe (upstream timeouts up to 300 s).

Shutdown and cancellation are handled deliberatelystrength

ProxyServer.AcceptLoopAsync retains the in-flight GetContextAsync() task and attaches an OnlyOnFaulted continuation so the ObjectDisposedException from a cancelled listener is observed rather than surfacing as an unobserved task exception. The same pattern is mirrored in McpServerHost. StopAsync correctly uses Close() alone and documents that a separate Stop() is redundant.

Backpressure replaces an unbounded queuestrength

Dispatch is gated by a semaphore sized from settings, with a 5-second acquire timeout and an explicit 503 shed. The shed is recorded through an infallible RecordRejectedRequest, so load shedding is visible in the Non-proxied log instead of vanishing. Shedding with a recorded reason is the right choice for a local proxy and is frequently skipped in tools like this.

Persistence has a designed failure pathstrength

SystemLogDbSink tracks consecutive failures, flips to a CLEF file fallback after three, keeps writing every event through the fallback, and retries the database every 30 s, replaying the event that triggered recovery. StatisticsService uses a bounded channel with a single dedicated writer and documents why FullMode.Wait plus non-blocking TryWrite was chosen over DropNewest (so overflow is detectable). Both are correct and unusually well reasoned.

Security boundaries are stated and enforcedstrength

ShouldSkipRequestHeader drops Host, Content-Length, Transfer-Encoding, Connection, Forwarded, X-Real-IP and all X-Forwarded-* so a direct client cannot spoof a trusted edge. Authorization headers are redacted from stored request logs (line 3925). The URL-ACL failure path emits the exact netsh http add urlacl command rather than a generic access-denied message.

Test coverage is broad and conformance-orientedstrength

40 test files, including vendor-spec conformance, SSE frame parity, request-payload parity, Ollama IR parity, schema migration, crash logging, compaction concurrency and request-logging coverage. The presence of parity suites (RequestPayloadParityTests, OpenAiSseFrameParityTests, OllamaIrParityTests) suggests translation regressions are caught mechanically rather than by inspection.

Clean separation where it countsstrength

All SQLite access sits in Infrastructure; module contracts live in Core and are narrow (IKaeoModule, IMcpToolModule, ISecretProvider, IModuleDatabase); the module loader uses its own ModuleAssemblyLoadContext. Translation logic was extracted into Services/Translation/ rather than living in the handler, which is why roughly 1,100 lines of the handler are delegating rather than parsing.

5Issues & defects

Ordered by consequence, not by how easy they are to fix.

5.1Client bearer tokens on /v1/* are relayed to the configured upstream

Inbound credentials are forwarded verbatim to a third-party base URLhighsecurity

The passthrough path copies every request header except the seven in ShouldSkipRequestHeader, and the code comment states the intent explicitly: a client's own bearer token is forwarded so that mappings without their own credential still work.

// OllamaProxyHandler.cs:1922 // Authorization is copied here so a client's own bearer token (e.g. Visual // Studio's OpenAI-compatible model connection) reaches the upstream for // mappings without their own configured credential. ApplyApiKey below overrides // this with the mapping's resolved credential secret when one is configured.

A search for inbound authentication in the Services assembly found no 401 path, no API-token check and no client-side credential validation — the only Authorization handling is outbound (lines 1131, 1975 and the compaction service). Combined with a listener that can be bound to 0.0.0.0, this means any process that can reach the port can drive the proxy and have its Authorization header delivered to whatever base URL a mapping points at.

Why it matters here specifically. Request logs redact Authorization, which shows the team already treats it as sensitive — but redacting the audit trail while relaying the value to a remote host protects the wrong copy. For a local-only listener bound to localhost the exposure is small; the moment a user follows the tray's "listen on all interfaces" path or binds a NIC IP, it becomes an exfiltration primitive.

Suggested direction. Make forwarding an explicit opt-in on the mapping (for example ForwardClientAuthorization, default off) and only emit the header for mappings whose base URL is loopback or in an allow-list. Alternatively require a proxy-issued token for non-loopback binds.

5.2One live settings object is shared between the UI thread and every request thread

Mutable settings are read by concurrent requests while WinForms mutates themmediumconcurrency

OllamaProxyHandler holds private volatile AppSettings _settings (line 34) and swaps the reference in UpdateSettings (line 96), which is the right primitive for a reference swap. The gap is what happens between saves: the Settings tabs operate on that same AppSettings instance, so collections such as the model-mapping list, the module registry and the credential list are mutated live while request threads enumerate them.

AppSettings is 1,794 lines with Normalize(), Clone(), CreateRuntimeSettings(), ApplyRuntimeSettings(), RefreshCompactionTargetNames() and seven Find* lookups on the same type, and every request path calls into it (ResolveModelName, FindModelMapping, ResolveApiKey, GetEffectiveContextWindow). Concurrent enumeration of a list being edited from the UI is a classic InvalidOperationException — and once requests have started, a stale or half-applied mapping produces authentication failures that look like upstream faults.

Suggested direction. Have the UI edit a draft AppSettings, then publish an immutable runtime snapshot on save (the existing RuntimeSettings type is already the right shape). Request threads read only the snapshot; the persisted DTO never crosses a thread boundary.

5.3Verb-agnostic stub classification swallows genuine 404s

Classifier and routing table disagree on /api/ps and /api/showmediumobservability

The classifier matches on path only:

// OllamaProxyHandler.cs:1318 if (path is "/api/ps" or "/api/show") return NonProxiedCategory.LocalStubs;

but the routing table is verb-scoped: /api/ps requires GET (line 1452) and /api/show requires POST (line 1456). A POST /api/ps or a GET /api/show therefore falls to the 404 branch at line 1521, gets a body and status recorded, and is then filed under LocalStubs.

Impact. The Settings UI exposes per-category capture toggles, so a user who silences routine stub noise also silences the malformed calls worth investigating. This is a small fix: pass the verb through to the classifier and match GET/POST exactly as the router does.

5.6Ordinal-based row mapping in the persistence layer

Reads are positional, so column order is an unstated contractlowmaintainability

AppDatabase is 2,614 lines and maps rows by index, for example AllowMultipleInstances = ReadBoolean(reader, 2) at line 649. Six tables are created in the same script (requests, mcp_requests, non_proxied_requests, model_mappings, system_logs, module_registry, credentials, runtime_settings) and the code already has a hand-rolled reconciliation step because CREATE TABLE IF NOT EXISTS cannot add columns. Inserting a column anywhere but the end silently shifts every later ordinal.

Suggested direction. Map by name (reader.GetOrdinal(name) cached per reader, or a small column-index table) so a schema edit fails loudly instead of reading the wrong field. This is worth doing before the next migration.

5.7Rapid settings saves spawn a poller task per save

Superseded-client disposal polls at 250 ms for up to five minuteslowefficiency

UpdateSettings starts a background task per save that polls the in-flight counter every 250 ms until it hits zero or five minutes elapse, then disposes the old client (lines 105–120). The concurrency reasoning is correct and documented, but a user toggling several settings under load creates one poller per save, each waking four times a second. A single disposal queue drained by one worker — or a TaskCompletionSource completed when the in-flight counter reaches zero — collapses N pollers into one waiter.

5.8Swallowed exceptions that hide real failures

Five empty catch blocks, two of which can mask a broken featurelow

Most empty catches are correct — ProxyServer.cs:251 and :281 deal with an already-aborted response, and InstructionFileLoader.cs:87 treats an unreadable instruction file as an empty one, which is defensible. Two are worth a second look: CodeVectorConfigPage.cs:182 (catch { } around loading credential names into the combo) and :514. If the secrets provider is unavailable, the combo silently renders empty and the user sees "no credentials configured" instead of "the credential store could not be read" — the exact failure the copilot-instructions' file-access guidance asks to log as a warning rather than absorb.

The only build-level configuration is Directory.Build.props (591 bytes) and the per-project NoWarn entries. Important scope note. The proxy is not itself AOT-compatible today: it dynamically loads modules via ModuleAssemblyLoadContext and uses reflection. Enabling PublishAot requires removing that capability, so the two upgrades are mutually exclusive for the proxy project. If a small single-file binary matters more than the module system, the OpenAPI package plus the ASP.NET Core host is the path; if the module system stays, keep the current hosting model and take the routing and OpenAPI wins individually.

9.2Derive the OpenAPI document from the routes

A hand-written spec that mirrors the router is a third copy of the truthupgrade

The explorer's OpenApiSpec literal (referenced from OllamaProxyHandler:1442) is maintained separately from the routing table and from Proxy API Mapping Documentation.html. Once routing is declarative, the spec can be produced by the framework, eliminating the drift risk entirely and removing a large block from the hub file.

9.3Adopt IHttpClientFactory in the extension

Pooling and handler rotation without new dependenciesupgrade

The Packages.config-free net48 VSIX already carries Microsoft.Extensions.*. Using IHttpClientFactory there (and in the modules) gives handler lifetime management, named clients with per-client timeouts and central default headers, and removes the per-call new HttpClient() instances identified in finding 5.4. For the proxy host, a single long-lived client is already correct — this upgrade is aimed at the VSIX and the modules.

9.4Structured logging plus request correlation

Serilog and a RequestId context are already in place; the next step is metricsupgrade

HandleAsync already pushes RequestId into Serilog.Context.LogContext, which is exactly the right hook. Adding System.Diagnostics.Metrics counters (active requests, shed count, upstream latency histogram by model, compaction duration) would let the dashboard show trends rather than only counts, and the Meter API is in the shared framework, so no package is needed.

9.5Continuous integration

There is no build pipeline, despite a GitHub remote and 40 test filesupgrade

.github/ contains only the copilot instructions file — no workflow. With three target frameworks (net10.0, netstandard2.0, net48) a single dotnet build on a developer machine does not prove the VSIX still compiles. A minimal workflow that restores, builds all TFMs, runs the test project and uploads the VSIX artifact would gate every PR and pay for itself the first time a netstandard2.0 API is used by accident.

9.6Optional: central package management

Version alignment across ten projectsupgrade

The host already overrides a transitive MessagePack to resolve known vulnerabilities, which is precisely the situation Directory.Packages.props with ManagePackageVersionsCentrally is designed for: one place to bump a version, and one place to audit for advisories across all projects.

Overall read. This is a carefully built codebase with an unusually strong comment culture, deliberate backpressure, a designed persistence failure path and broad parity testing. The defects worth acting on are concentrated in three places: outbound credential handling on a listener that can be bound to all interfaces, cross-thread sharing of the mutable settings object, and hygiene around a hub file that has outgrown a single-screen mental model.
