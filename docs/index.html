Kaeo LLM Proxy

View on GitHub Releases

Kaeo LLM Proxy is a C# Windows system-tray application that acts as an Ollama API-compatible proxy in front of one or more llama.cpp servers and other OpenAI-compatible upstreams. It lets Ollama clients talk to backends that expose a /v1/ API instead of the native Ollama API.

Why this exists

Many local AI tools expect the Ollama REST API, while llama.cpp and similar servers often expose an OpenAI-compatible API. This proxy sits in between, listening on localhost:11434 by default, rewriting requests and responses as needed, and routing each request to the correct upstream model.

Key features

  • Ollama-to-OpenAI/llama.cpp request and response translation
  • Transparent /v1/* passthrough for OpenAI-compatible clients and SDKs
  • Streaming and non-streaming chat/completion support
  • Streaming tool-call rewriting, including conversion of inline XML tool calls
  • Thinking/reasoning support: Ollama think input, message.thinking output, and reasoning_content compatibility for clients that expect visible assistant text
  • Per-model reasoning effort configuration — value list, selection, Client App / Proxy / Provider priority, and multiple upstream wire formats (top-level reasoning_effort, nested reasoning, Qwen Cloud extra_body, and chat_template_kwargs)
  • Per-model Thinking Handling mode to leave inline <think> blocks in place, move them into reasoning_content / message.thinking, strip them, or handle Qwen [Thinking]/[Answer] markers
  • Per-model context-window reporting (context_length) advertised to clients such as GitHub Copilot for accurate context metering
  • Vision (base64 image) input passthrough for multimodal models
  • Model name mapping with per-model upstream URL, timeout, credential, sampling, and behavior settings
  • Optional instruction set injection for model-specific system prompts
  • Streaming heartbeats and periodic upstream heartbeat monitoring, with a live per-model heartbeat view
  • Automatic conversation summarization retries when context windows overflow
  • Built-in MCP (Model Context Protocol) server over Streamable HTTP at /mcp, with an optional Scalar API explorer and OpenAPI document
  • Importable MCP sub-modules that contribute tools to the built-in server (Web Search, SSH, Code Vector Store), loaded in isolation with their own config and help pages
  • Centralized encrypted credential store referenced by name from model mappings and module providers
  • Request/response redaction, including field-level redaction of sensitive JSON keys (API keys, tokens, secrets)
  • Test console for sending chat requests through the proxy with streamed output
  • Portable Windows tray app with LiteDB-backed request history and Serilog app logging

MCP server and modules

The proxy embeds an MCP server (default http://localhost:8388/mcp) that exposes the tools contributed by the loaded sub-modules over the Streamable HTTP transport. Clients speak JSON-RPC 2.0: post an initialize request to open a session (the response carries an Mcp-Session-Id header), then send tools/list and tools/call on the same session. Sub-modules are importable .dll assemblies built against the Kaeo LLM Proxy module contracts; the host loads each in an isolated context and contributes its tools, configuration page, and help content. Ships with:

  • Web Search — web_search / web_fetch tools
  • SSH — remote shell execution tools
  • Code Vector Store — semantic code indexing and search (code_index, code_search, code_status, etc.)

Configuration highlights

  • ListenPort and ListenAddress configure where the proxy listens; a separate MCP server section (port, address, auth, API explorer) controls the /mcp endpoint
  • The Logging section controls app logs, retention, and database location
  • Model mappings define the proxy-facing name, upstream model, upstream URL, timeout, credential, and feature toggles
  • Per-model settings can enable thinking compatibility, streaming heartbeats, summarization, instruction sets, response redaction, context-window override, and reasoning effort
  • Credentials stores named secrets encrypted at rest, referenced by name from model mappings and module providers
  • The MCP Modules page imports and manages the sub-modules that contribute tools to the built-in MCP server

Quick start

  1. Install the .NET 10 Desktop Runtime if needed.
  2. Run Kaeo LLM Proxy.exe; it starts minimised to the system tray.
  3. Open the dashboard from the tray icon.
  4. Add one or more model mappings that point to your llama.cpp or compatible upstream servers.
  5. Optionally configure instruction sets, heartbeats, and logging/redaction settings.
  6. Point your Ollama-compatible client at http://localhost:11434.

Networking and security

  • Default binding is localhost, which keeps access local to the machine.
  • Binding to 0.0.0.0 or a specific external IP may require administrator rights or a URL ACL reservation (for both the proxy listener and the MCP server on its own port).
  • Prefer request/response redaction when prompts or outputs may contain sensitive information.
  • Use HTTPS upstream endpoints where possible if the upstream is remote.
  • The MCP server supports an optional bearer-token credential (by name) and a field-level redaction of sensitive JSON keys when capturing MCP request/response details.
